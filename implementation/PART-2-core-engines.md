## Step 2 — Behavioral engine (gate: persona fingerprints match expectations)

`backend/app/engines/behavioral.py` → `compute_fingerprint(fi_json) -> Fingerprint`, pure pandas, no I/O:

- `savings_ratio` = (credits − debits)/credits over trailing 3 months.
- `spend_leaks[]` = top merchant-category monthly spends from a **closed category map** (`data/category_map.yaml`: narration regex → category code like `FOOD_DELIVERY`, `SUBSCRIPTION`). Raw narrations never leave this module.
- `sip_discipline` = fraction of last 12 months with an on-time SIP debit (0–1).
- `idle_cash` = avg balance above 2× monthly expenses (paise).
- `insurance_gap` = heuristic: term cover proxy vs 10× annual income.
- `risk_capacity` = LOW/MEDIUM/HIGH from age + savings_ratio + sip_discipline rubric (document the rubric in the docstring).
- Every field wrapped `{value, as_of, confidence}`.

**Gate:** `pytest tests/test_behavioral.py` — one test per persona asserting the headline facts (e.g. `idle_cash` persona ≥ ₹3.0L idle; `young_spender` has `FOOD_DELIVERY` leak ≥ ₹4,000/mo).

## Step 3 — Advisory + projection + suitability engines (gate: golden fixtures pass)

1. `backend/app/data/product_shelf.yaml`: IDBI FD ladder rates, index MF entries, Suvidha SIP, term insurance — each with `product_id, name, rate/ter, min_amount`.
2. `backend/app/data/strategy_library.yaml`: the 10 PRD §3A strategies as `id, source_principle, trigger_conditions (fingerprint predicates), allocation_template, explanation_snippet`.
3. `backend/app/engines/advisory.py` → `advise(fingerprint, goals) -> list[Recommendation]`:
   - Evaluate triggers top-down; each Recommendation = `{action, product_ref, amount_paise, allocation, strategy_id, reasoning_trace, numeric_claims}`.
   - `reasoning_trace` = `{strategy_id, source_principle, inputs_used, math_steps[], engine_ver, shelf_sha, strategy_sha}` (shas = sha256 of the YAML file bytes, first 12 hex).
   - `numeric_claims` = every display string the narrator may utter (`"₹3.2 लाख"/"₹3.2 lakh"`, `"₹14,000"`, `"6.8%"`, `"20 साल"`) — generated by one formatter `app/engines/money.py` (`paise → "₹X.Y lakh/crore"`; the ONLY place formatting happens).
4. `backend/app/engines/projection.py` → deterministic SIP future value, FD ladder yield, retirement corpus, and `future_self(fingerprint, take_advice: bool) -> ProjectionScript` (good/bad branch, 30-year, conservative 10%/6.5% nominal; returns first-person script lines each backed by numeric_claims).
5. `backend/app/engines/suitability.py` → `screen(fingerprint, recommendations) -> list[Recommendation]` — the investor-protection gate, runs **after** advisory, **before** narration. Each recommendation is PASS / SOFTEN / VETO against rules in `data/suitability_rules.yaml`: e.g. veto aggressive-equity tilts for `age ≥ 50` or `risk_capacity LOW`; veto any single-asset allocation > 30% (concentration); veto amounts exceeding declared idle/surplus. A VETO carries a `refusal_reason` that lands in the `reasoning_trace` — the engine must be able to *decline and explain*, not just recommend. Vetoed recs never reach the narrator.

**Gate:** `pytest tests/test_advisory.py tests/test_projection.py tests/test_suitability.py` — golden fixture per persona (`tests/golden/{persona}.json`): assert strategy chosen, amounts exact to the paisa, every trace pins both shas; determinism test: run twice, byte-identical output; suitability test: `near_retiree` persona is never handed an aggressive-equity rec and the refusal_reason is present in the trace.
